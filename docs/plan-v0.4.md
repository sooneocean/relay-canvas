## Proposed shared/API design (freeze after security and plan review)

Separate Timeline per board, revision independent of Board. Timeline {boardId,revision,format:'landscape'|'portrait',clips:TimelineClip[]}. Clip {id,source:{runId,nodeId,artifactIndex},inSeconds,outSeconds,artifact:Artifact,media:{duration,width,height,hasAudio}}. Canonical artifact/media fields are resolved by server, never accepted from caller. PUT input {expectedRevision,format,clips:[{id,source,inSeconds,outSeconds}]}. Repeated source clips are allowed, clip IDs unique. Sources must be saved succeeded video artifacts belonging to that board; current runs are never pruned automatically (existing 200 run cap remains). Probe only local saved media, with signature+container validation and actual metadata. Validate finite times, 0 <= in < out <= probed duration, minimum 1/24 second; max 12 clips, 60s source trim per clip, total <=180s, source <=3840x2160 or equivalent pixel bound. Empty timeline can be saved but cannot export.

GET /api/boards/:id/timeline returns empty rev0 default if none; PUT saves with CAS. GET /api/runs/:runId/artifacts/:nodeId/:index/info returns local probed video metadata; rejects unsaved sources (UI offers existing explicit save). GET /api/editor/capabilities gives safe ffmpeg/ffprobe availability booleans and fixed format limits, never filesystem paths/stderr. POST /api/boards/:id/exports {expectedRevision,operationId} =>202 ExportJob. GET /api/exports/:id; POST /api/exports/:id/cancel {}. ExportJob {id,boardId,timelineRevision,operationId,status,startedAt,finishedAt?,error?,snapshot:Timeline,artifact?}. Max 100 retained jobs, 1 active job globally; reject busy instead of an unbounded queue. Same operationId returns same job before scheduling; mismatch board/revision =>409. Restart pending/running =>interrupted. Export asset persists in exports and becomes an authorized reference for /api/media. GET /api/boards/:id/compare?left=runId&right=runId returns immutable runs and explicit node-level differences; reject mixed-board runs.

MediaStore needs an internal trusted byte-commit path for generated MP4, using the same hash/quota/atomic commit/reference retention protections as v0.3. No arbitrary path/URL/headers enter public export API. Export artifact.url and localUrl point to the private local route; this is a post-production artifact, not a provider generation result. Export metadata is checked on load and counted as a media reference for failure reconciliation. Existing saved media remains eligible even if its source URL expires.

## Process and filesystem security proposal

Use system ffmpeg/ffprobe (minimum FFmpeg 5, libx264 and AAC required); missing binaries disable export/probe with a safe actionable message while generation remains usable. Do not bundle third-party binaries. Fixed commands use spawn(executable,args,{shell:false}), -nostdin, no caller command/filter/path/codec parameters. Only server-created private job paths and validated numbers enter args. Existing media.fileFor supplies verified nofollow fd; copy bounded bytes from that fd into a new private job directory, then close fd. Never hand FFmpeg original remote URLs or caller-controlled file paths. Source .mp4 uses forced mov demuxer with external drefs disabled and absolute aliases disabled; source WebM uses forced matroska demuxer. Restrict protocol whitelist to local file/pipe and format whitelist to required containers. No playlists, concat URL protocols, arbitrary filter graphs, subtitles or imported scripts. Preserve default TLS safeguards elsewhere.

Probe timeout 10s, bounded stdout/stderr, max_alloc 64MiB, probe/analyze bounds; render overall deadline 180s, threads 2, fixed output dimensions/fps, max 64MiB output, workspace 512MiB quota unchanged. Normalize one clip at a time, remove copied source after each segment, cap total normalized segments to 64MiB, final concat stream-copy fixed generated segment manifest; max temporary footprint 192MiB plus bounded overhead. Use faststart MP4; pad/trim/resample audio explicitly to clip length. Do not expose stderr, physical paths, URLs, environment or secrets in API errors. Abort must terminate child, escalate if necessary, clean only owned job files, and never mark partial output succeeded. Secure job root must reject preexisting/replaced symlink/non-directory before any chmod/write/remove; retain trusted identity. No unrestricted recursive removal of a caller path. FFmpeg parses untrusted media; OS-native codec bugs are not proven absent by application guards. Test FFmpeg on local fixtures only, no externally uploaded source in this release verification.

## Frozen revision RC-V04-R1 (supersedes draft alternatives)

Root accepts security findings RC-V04-SEC-01..04 and their remediation before implementation. Request final security READY and then plan READY against this revision. Root explicitly accepts residual codec memory-safety risk from running a maintained OS FFmpeg with the user's privileges; protocol/path/process guards are not an OS codec sandbox. No claim that local fixture testing proves remote codec safety. Supported export hosts: macOS/Linux, maintained system FFmpeg/ffprobe major >=6 with libx264/AAC and required safe demux options; operators must keep distribution security patches current. Capability detection fails closed for missing/incompatible binaries/options/encoders. Generation and comparison remain usable without these tools.

- SEC-01: every probe/export source is copied solely from existing MediaStore O_NOFOLLOW fd, using bounded reads and SHA-256 while copying. Require exact artifact.bytes/hash, regular file and matching fstat identity before/after copy, private destination wx/0600; no subprocess before integrity validation. Same-length tampering is an explicit negative test. Source URLs never become arguments.
- SEC-02: resolve system binaries once to canonical absolute executable regular files, reject workspace-contained executables, skip relative/empty PATH entries, and revalidate dev/ino/regular executable identity before every invocation. Operator environment is trusted configuration, not an API input. Use a sanitized subprocess environment, owned private cwd, bounded stdout/stderr and generic safe errors. Per MP4 input immediately before -i: -f mov -protocol_whitelist file -enable_drefs 0 -use_absolute_path 0; WebM: -f matroska -protocol_whitelist file. Explicit first-video and optional first-audio map, no subtitle/data/attachments. Server-generated segment concat manifest uses fixed relative basenames, -f concat -safe 1 -protocol_whitelist file. No pipe, network, concat URL, playlist or caller filters. Test malicious PATH, option placement, absolute/relative dref and manifest/protocol escape fixtures. -max_alloc is a single-allocation bound, not a total-RSS sandbox.
- SEC-03: quotas are explicitly separate: persistent content-addressed media <=512MiB; ephemeral editor files <=192MiB globally, including retained crash remnants. One render reservation owns its temporary budget; probe admission also consumes that budget and cannot overbook it. Source copies <=64MiB; rendered segments cumulative <=64MiB; final MP4 <=64MiB. Hold a persistent-space reservation in the same serialized MediaStore authority used by ordinary saves, so concurrent saves cannot consume reserved bytes; reserve min(64MiB, available persistent bytes), not necessarily the full cap, and reject zero space. Render -fs uses remaining reserved output/segment budget +1; after every process close fstat regular file/actual bytes and enforce both segment and temporary totals. Commit derived bytes/fd through the same MediaStore queue, consuming its reservation atomically and releasing it on all terminal paths. Never expose a caller file path to this internal commit. Missing space, concurrent saves and output+1 tests must cover actual enforcement.
- SEC-04: persist job+snapshot+random attempt nonce atomically before any subprocess, lookup global operationId before capacity/busy checks, and require expected timeline revision. Every progress/success/failure/commit must match attempt nonce and current nonterminal status; cancellation is persisted before signalling. All children run under a dedicated Node supervisor with a private IPC channel to the server. Supervisor owns the actual FFmpeg process group, independently bounds runtime, and on parent IPC disconnect (including server SIGKILL) sends TERM then KILL after <=1s and awaits close. Parent cancellation uses the same path; never kill the supervisor before its child group closes. Test real server SIGKILL/restart while a child is alive: survivor stops writing, job remains interrupted, no late success/media commit. Private job directories use new unpredictable identities, never reuse paths; cleanup checks trusted root/job identity and removes only server-owned known filenames, not arbitrary recursive paths. Unknown remnants are retained/quarantined and counted toward temporary quota, never silently deleted. No pid/path/argv/env in public or workspace job records; supervisor bookkeeping is private and ephemeral. Tests include cancel/finish races and failed durable job creation causing zero spawn.
- Strict capped load schemas validate timelines, snapshots and exports (20 timelines/12 clips, 100 jobs, 180s); artifact metadata validation, persisted reference reconciliation and media authorization include exported artifacts. Pending/running jobs become interrupted at startup with no replay. Existing run cap already rejects at 200, so there is no pruning that can invalidate timeline sources.
- Probe admission is bounded (at most two probes), no unbounded queue; timeline PUT validates sources in sequence, then rechecks timeline CAS before commit. Export's 180s total deadline includes normalization/concat and cancellation; each probe also has a 10s supervisor deadline. Job/snapshot publication and status updates are serialized through Store transactions. Internal tests may inject runners for deterministic failure paths but real FFmpeg color/audio/output and crash tests are mandatory.

API/type names and ownership above remain the frozen frontend/backend contract. Backend may choose internal modules/helpers without altering those public shapes; report any required public adjustment before changing it. Timelines are independent of canvas revisions. Root tests and builds only after owners return a stable candidate.

### MCP journey completion addendum

In addition to read/update timeline, export/status/cancel and compare, expose `save_artifact` and `get_artifact_info` as strict wrappers around the already authorized artifact-save and local-only info endpoints. This allows Codex to perform the complete generation → explicit local save → timeline → export journey without a human UI detour. These tools do not accept URLs, paths, headers or credentials and do not regenerate; save is an explicit bounded network download when the source is remote. Total tools: 17 (existing 9 + 8), replacing the provisional 15-tool count in the implementation brief. No HTTP, shared schema, authorization, subprocess or storage contract changes. Root requests a bounded review of this addition while backend implementation continues within previously approved scope.

Both wrappers accept exactly `{runId,nodeId,artifactIndex}`: existing strict ID regex for the two IDs, artifactIndex integer 0..99 (the persisted artifact-array cap), no extra keys. save_artifact uses only the fixed identity route and an empty `{}` HTTP body; info is GET of that same identity. Neither wrapper accepts URL/path/header/credential. Negative MCP tests reject illegal IDs, negative/fractional/over-limit index and every extra field. A real stdio SDK handshake using Demo/controlled fixtures must show info-before-save failure, then save→info read-back matching HTTP/state artifact identity, bytes and SHA-256, with no regeneration or second download and no workspace-external write. No paid generation.
