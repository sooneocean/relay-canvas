### Protocol and diagnostics

`Protocol` adds `videos`. New API is an `openai` image profile with a custom base ending in /v1, not a distinct API implementation. Image parameters retain the existing strict bounded schema. `videos` params permit only `seconds` (string enum 4/8/12), `size` (string enum 720x1280/1280x720/1024x1792/1792x1024); unknown keys/type/range rejected before POST. model and prompt come only from request; optional input_reference is constructed as {image_url:originalReferenceUrl}, never supplied via params. POST {base}/videos returns {id,status,...}; id grammar ^[A-Za-z0-9_-]{1,200}$; poll GET {base}/videos/{id}. queued/in_progress continue, completed reads only top-level url or video_url, failed stops; other shapes/statuses stop. A completed create may finish immediately only after onSubmitted persists ID. Missing completed URL reports unsupported content response. No /content proxy, no generic body/path mapping, no official OpenAI/Sora availability claim. Fixtures, not paid live, prove this contract. Original image adapter's unsupported reference still rejects before POST.

GET /api/providers/diagnostics returns array of {providerId,configurationValid,remoteEnabled,credentialConfigured,capabilities:('image'|'video')[],codes:string[]}. Boolean credential presence means own env property nonempty and <=16384 chars, never validity, length/hash/value. Codes are fixed safe values. GET /api/providers/:id/models operates on saved profile only, Demo returns its fixed models without network; openai/videos only uses fixed GET base/models and existing guarded transport/Bearer env key, requires remote enable + valid origin/key. Other protocols explicitly unsupported/manual fallback. Return {models:string[]} max500 IDs <=200 chars, restricted printable model grammar, dedup; never raw upstream objects/errors. Reject any ID containing the configured secret. No generation request for diagnostics/discovery.

### Media and schema

Artifact optional additive fields: localId?:string; localUrl?:string; bytes?:number; sha256?:string; mimeType already exists. Both localId/sha256 are lowercase 64-hex content hash, not an authorization credential. localUrl=/api/media/{hash}. Original artifact.url remains unchanged and is the only upstream provider reference. Existing v0.2 workspaces load unchanged in v0.3. v0.3 videos profiles are NOT readable by v0.2's enum: downgrade requires the byte-identical private workspace.pre-v0.3.json backup created once before the first v0.3 rewrite. Preserve newer workspace and media directory before manual restoration; code rollback alone is not data rollback. Tests load a fixed v0.2 fixture, compare backup bytes, upgrade/save/restart and verify board/run/profile/remote URL preservation; verify backup through legacy v0.2 provider grammar. Never operate on the user's live runtime for this test.

Explicit POST /api/runs/:runId/artifacts/:nodeId/:index/save with strict {} body only. Source must be existing succeeded run AND node AND valid artifact index. No caller URL/path/headers. Invalid input400, unknown404, not succeeded409. Allow PNG (signature+IHDR), JPEG(FFD8...FFD9), WebP(RIFF/WEBP bounded declared length), MP4(ftyp box), WebM(EBML header); MIME header/data prefix must match the detected signature. Signature validation is not a full codec decoder or proof of a non-corrupt complete movie; failed playback remains visible, no full decoder dependency is introduced. Reject HTML, remote/imported SVG and unknown formats. Trusted server Demo SVG is the sole SVG exception: artifact.demo=true, originating snapshot provider.protocol=demo, fixed data:image/svg+xml;charset=utf-8 prefix; serve saved SVG with sandbox;default-src 'none' CSP and nosniff. Demo MP4 copies only the bundled fixed demo-motion.mp4, never a caller file path.

Fixed 64MiB cap for each file; 512MiB quota counts committed regular media files including crash orphans. Serialized persistence prevents concurrent quota races. Known existing content metadata returns without download; duplicate newly downloaded hash doesn't consume quota twice. Temp downloads are bounded at 64MiB and one writer at a time. Use GET only, current exact media allowlist, reject every redirect, all DNS addresses public, pinned TLS lookup, 30s total deadline, declared and actual byte caps and Content-Length mismatch check. Data URL base64 is bounded; no credentials forwarded to media hosts. Buffering <=64MiB is acceptable for this release. Store media directory0700, files0600; opaque temp wx/no symlink, hash basename+server-chosen extension, path containment/no-follow validation. File fsync/rename/fsync-dir precedes atomic metadata. If metadata write fails, remove only the newly created unreferenced content file; never remove existing/dedup content. On errors: no temp/metadata/partial file; succeeded run/node and original URL unchanged. UI owns transient save failure status separately and retry only resaves. Crash between durable file and metadata may leave an orphan counted toward quota, never partial referenced media; do not delete unknown orphan files automatically.

### Media authorization RC-V03-AUTH-R1

Bootstrap GET /api/session sets relay_canvas_media=<current random session token>; HttpOnly; SameSite=Strict; Path=/api/media, with no Domain/Max-Age/Expires. Local HTTP cannot set Secure; loopback only, token rotates every restart. No URL token. Ordinary API still requires header token, never cookie. Only GET/HEAD /api/media/:localId accepts valid header token (existing exact Origin rules) OR scoped cookie (must include Sec-Fetch-Site:same-origin and Origin, if present, exact). All routes retain exact Host and cross-Origin rejection. Bounded cookie parser rejects malformed/duplicate values and uses timingSafe token comparison. Bad auth403 before ID lookup. ID must match lowercase SHA256 and be referenced by current workspace artifact metadata before deriving a trusted basename. Unknown ID404. MIME/nosniff/CORP same-origin/Content-Length; GET full200 or one valid bytes Range206, Content-Range correct; malformed/multi/unsatisfiable Range416, HEAD zero body. Fixed-root sendFile only after containment/symlink validation, never arbitrary route-derived path. No deletion API.
